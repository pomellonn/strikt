# Подготовка датасета для дообучения эмбеддера (contrastive learning, дедубликация)

Задача: дообучить эмбеддер различать три класса связи между парами коротких
русскоязычных «объектов»:

- **duplicate** — один и тот же объект в разных формулировках
- **similar_not_duplicate** — похожая тема, но разные сущности
- **not_duplicate** — совершенно разные темы

## Пайплайн 

1. `objects3.csv` — исходный список объектов (сырые тексты)
2. `pairs_labeled.ipynb` — основной ноутбук, весь пайплайн от сырых данных до сплитов
3. Внутри ноутбука: очистка → лемматизация → эмбеддинги (sentence-transformers,
   multilingual mpnet) → полная матрица косинусной близости → сортировка пар по убыванию
4. Верхние пары по схожести отбираются для ручной разметки, автодубликаты по лемме — отдельно
5. Всё объединяется в один файл, строится граф identity-связей и сплит train/val/test

## Файлы

| Файл | Что внутри | Как получен |
|---|---|---|
| `objects3.csv` | ~5300 сырых объектов | исходные данные |
| `auto_duplicates.csv` | 126 пар, класс `duplicate` | точное совпадение по лемма-сигнатуре — не требует ручной проверки |
| `pairs_to_label.csv` `pairs_to_label2.csv` | 4000 пар по cosine similarity | пары для разметки |
| `pairs_labeled.csv` `pairs_labeled2.csv` | те же 3000 пар, `connection` заполнен | размечено Claude + ручная проверка |
| `objects3_pairs_labeled.csv` | 4122 пары после объединения и удаления дублей | `auto_duplicates` + `pairs_labeled` + `pairs_labeled2`, drop_duplicates по (object_1, object_2) |
| `datasets for training/train.csv` | 2842 пары | финальный train |
| `datasets for training/val.csv` | 575 пар | финальный val |
| `datasets for training/test.csv` | 705 пар | финальный test |

Итоговое распределение классов (`objects3_pairs_labeled.csv`, 4122 пары):
duplicate — 1002, similar_not_duplicate — 218, not_duplicate — 2902.

## Как считался train/val/test


1. Строится граф связей **только по duplicate-рёбрам** — это единственный случай,
   когда две строки действительно об одной и той же сущности. Компоненты графа
   (1306 штук, самая крупная — 33 объекта) — это identity-кластеры.
   (not_duplicate-пары в граф не включаются: если их тоже связывать, через частые
   «узловые» темы почти весь датасет транзитивно слипается в одну гигантскую группу.)
2. Группа для сплита — неупорядоченная пара кластеров (object_1, object_2) этой строки,
   а не кластер одного object_1 — иначе identity могла утечь через вторую колонку.
3. `StratifiedGroupKFold` (5 фолдов, random_state=42), сначала outer-сплит
   train+val/test, затем inner-сплит train/val.

Проверено: пересечений групп между train/val/test нет (TRAIN∩VAL = TRAIN∩TEST = VAL∩TEST = 0).
